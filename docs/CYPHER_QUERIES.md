## find_entry_points

Anchor an unstructured security alert to graph nodes. Call this FIRST when you only have raw alert text or an incident description and do not yet know which CVE / package / service is involved. Runs a hybrid search on FalkorDB: HNSW vector KNN over `Vulnerability.embedding` (`CALL db.idx.vector.queryNodes`) plus full-text search over `Vulnerability.summary` (`CALL db.idx.fulltext.queryNodes`), merges the candidates, then expands each one 4 hops (Vulnerability -> Package <- Function <- CALLS*0..3 <- Function <- DEPLOYS_CODE <- Service) so you learn which packages, functions and production services are reachable from the alert. Returns matches sorted by combined score with `best_cve_id`; pass that id to `trace_blast_radius`.

Called with `{"alert_text": "WAF observed 1,240 bearer tokens with forged kid headers accepted by auth-token-service in 4 minutes; signature verification bypass suspected in jwt-crypto-core (deserialization path)", "top_k": 3}`.

```cypher
CALL db.idx.vector.queryNodes('Vulnerability', 'embedding', $k, vecf32($vec))
YIELD node, score
RETURN node.id, node.severity, node.cvss, node.summary, score
ORDER BY score ASC
```

graph: `prod`, 0.078 ms server time, 3 rows, params: `{"k": 3, "vec": "<list[384]>"}`

```cypher
CALL db.idx.fulltext.queryNodes('Vulnerability', $q)
YIELD node, score
RETURN node.id, node.severity, node.cvss, node.summary, score
ORDER BY score DESC
LIMIT $k
```

graph: `prod`, 0.32 ms server time, 2 rows, params: `{"q": "observed|bearer|tokens|forged|headers|accepted|authtokenservice|auth|token|service|minutes|signature", "k": 3}`

## trace_blast_radius

Trace the multi-hop blast radius of a CVE through code, services and cloud identity. Call this right after you know the CVE id (from `find_entry_points` or the incident) and again after a remediation to verify the exposure is gone. Single OpenCypher traversal across 5 hops: Vulnerability -AFFECTS-> Package <-IMPORTS- Function <-DEPLOYS_CODE- Service -ROUTES_TO*0..N-> Service -ASSUMES_ROLE-> IAMRole -CAN_ACCESS-> Database{contains_pii:true}, keeping only ACTIVE edges. Returns every exposed path (with pivot service, IAM role, PII database and hop counts), the distinct origin services, exposed databases and pivot services with path counts.

Called with `{"cve_id": "CVE-2026-8841", "max_route_hops": 3}`.

```cypher
MATCH (v:Vulnerability {id: $id})
RETURN v
```

graph: `prod`, 0.034 ms server time, 1 rows, params: `{"id": "CVE-2026-8841"}`

```cypher
MATCH (v:Vulnerability {id: $cve_id})-[:AFFECTS]->(p:Package)<-[:IMPORTS]-(f:Function)<-[:DEPLOYS_CODE]-(s:Service)
RETURN DISTINCT s.name
ORDER BY s.name
```

graph: `prod`, 0.428 ms server time, 1 rows, params: `{"cve_id": "CVE-2026-8841"}`

```cypher
MATCH (v:Vulnerability {id: $cve_id})-[:AFFECTS]->(pkg:Package)<-[:IMPORTS]-(f:Function)<-[:DEPLOYS_CODE]-(origin:Service)
WITH DISTINCT origin
MATCH attack = (origin)-[:ROUTES_TO*0..3]->(pivot:Service)-[:ASSUMES_ROLE]->(role:IAMRole)-[acc:CAN_ACCESS]->(db:Database {contains_pii: true})
WHERE ALL(r IN relationships(attack) WHERE coalesce(r.status, 'ACTIVE') = 'ACTIVE')
RETURN origin.name AS origin_service, pivot.name AS pivot_service, pivot.tier AS pivot_tier, pivot.rps AS pivot_rps, role.name AS iam_role, db.name AS database, db.classification AS classification, acc.access_mode AS access_mode, length(attack) - 2 AS route_hops, length(attack) AS total_hops, [n IN nodes(attack) | coalesce(n.name, n.id)] AS path_nodes, attack
ORDER BY total_hops ASC, pivot_service, database
```

graph: `prod`, 0.328 ms server time, 6 rows, params: `{"cve_id": "CVE-2026-8841"}`


## rank_service_criticality

Score every production service with FalkorDB's native graph algorithms so you can choose a remediation target mathematically instead of guessing. Call this before deciding which service to isolate. `CALL algo.pageRank('Service','ROUTES_TO')` = how architecturally critical a service is (high = too important to take offline); `CALL algo.betweenness({nodeLabels:['Service'], relationshipTypes:['ROUTES_TO']})` = how many shortest paths funnel through it (high = a lateral-movement chokepoint). Harmonic centrality is included when available. Never isolate a `tier: critical` service; prefer the non-critical pivot with the highest betweenness.

Called with `{}`.

```cypher
CALL algo.pageRank('Service', 'ROUTES_TO')
YIELD node, score
RETURN node.name, node.tier, node.rps, score
ORDER BY score DESC
```

## shortest_attack_path

Compute the exact shortest attack chain from a service to a database with FalkorDB's `algo.SPpaths` (relTypes ROUTES_TO, ASSUMES_ROLE, CAN_ACCESS). Use it to produce the concrete proof path for a decision or to check how many hops separate an entry point from a crown-jewel database. `active` tells you whether every edge on that path is still ACTIVE (false after a quarantine).

Called with `{"source_service": "auth-token-service", "target_database": "customer-kyc-vault-db"}`.

```cypher
MATCH (s:Service {name: $name})
RETURN s
```

graph: `prod`, 0.046 ms server time, 1 rows, params: `{"name": "auth-token-service"}`

```cypher
MATCH (src:Service {name: $src}), (dst:Database {name: $dst})
CALL algo.SPpaths({sourceNode: src, targetNode: dst, relTypes: ['ROUTES_TO', 'ASSUMES_ROLE', 'CAN_ACCESS'], maxLen: $max_len})
YIELD path, pathWeight
RETURN [n IN nodes(path) | coalesce(n.name, n.id)] AS path_nodes, pathWeight, length(path), ALL(r IN relationships(path) WHERE coalesce(r.status, 'ACTIVE') = 'ACTIVE') AS active, path
```

## execute_remediation

Execute the verified remediation on the production graph. Only call this AFTER `simulate_remediation` returned `safe_to_execute: true` for the same incident, CVE, bridge service and IAM role (the tool refuses otherwise, returning status REFUSED rather than acting). `justification` must cite the graph evidence (exposed paths, betweenness/pagerank, sandbox result). Actions, all surgical and reversible: flags every ACTIVE ROUTES_TO edge touching the bridge service as ISOLATED_BY_AEGIS, flags the IAM role's CAN_ACCESS edges as QUARANTINED_BY_AEGIS, marks the service ISOLATED and the role QUARANTINED, routes a draft pull request (package bump) to the code owner found in the graph, writes an immutable `ActionAudit` node (scores, proof paths, mutations, Cypher) linked to the incident and to the modified entities, then re-runs the exposure query. ## read_graph

Run an ad-hoc READ-ONLY OpenCypher query against the production graph when no other tool answers your question (e.g. "which services assume role X?" or "list developers on call"). Executed with GRAPH.RO_QUERY, so FalkorDB itself rejects any write; at most `limit` rows (max 500) are returned and the query is cancelled after 5 s. Labels: Vulnerability, Package, Function, Service, IAMRole, Database, Developer, Incident, ActionAudit. Called with `{"cypher": "MATCH (s:Service)-[:ASSUMES_ROLE]->(r:IAMRole) RETURN s.name, r.name"}`.
